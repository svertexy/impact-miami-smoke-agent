# Impact Miami Smoke-Test Agent\n\nA small, judge-friendly agent demo for Impact Miami. It reads a project dataset, summarizes delivery status, flags at-risk work, and cites the source records used for each conclusion.\n\n## What the agent does\n\n1. Loads the synthetic records in [sample-projects.json](sample-projects.json).\n2. Groups projects by status (on track, at risk, and blocked).\n3. Calculates a simple risk view from status, owner, and next action.\n4. Returns a concise project summary with source record names so a reviewer can verify each result.\n5. Keeps secrets out of the repository; runtime credentials belong in Vercel Environment Variables.\n\nThis is intentionally a smoke test: it proves the Verso/Vercel agent loop before adding a larger hackathon data source or voice layer.\n\n## Live demo status\n\nThe current Vercel deployment is online but still presents Vercel sign-in to anonymous visitors. The bot is therefore not yet a judge-ready public URL. Use the Vercel project link below to adjust deployment protection or test while signed in:\n\n- [Open the Vercel project](https://vercel.com/six-star-vision/impact-miami-smoke-agent)\n- [Open Vercel Environment Variables](https://vercel.com/six-star-vision/impact-miami-smoke-agent/settings/environment-variables)\n\n## Repository map\n\n- [agent-instructions.md](agent-instructions.md): the agent contract, input shape, output format, and responsible-AI constraints.\n- [sample-projects.json](sample-projects.json): synthetic records used for the demo; no private data.\n- [CLAUDE.md](CLAUDE.md): context for Claude Code and future implementation work.\n\n## Secure configuration\n\nConfigure runtime secrets only in Vercel Project Settings → Environment Variables. Never commit API keys or paste them into documentation. For OpenRouter, add `OPENROUTER_API_KEY` directly in the secure Vercel UI, select the environments needed, and redeploy.\n\n## Local smoke test\n\nUntil anonymous access is enabled, validate the agent contract locally or in the signed-in Vercel preview using the prompt: “Summarize the three sample projects and flag any at risk.” The expected result is a short table, Biscayne Transit Alerts flagged as at risk, and source record names.\n\n## Demo checklist\n\n- Use a small, known dataset first.\n- Show the status summary, one at-risk item, and the cited source record.\n- Explain that the records are synthetic and that production data would be connected through a secure backend.\n- Add ElevenLabs only after the text workflow is stable; voice is an optional presentation layer, not required for the core agent.\n
