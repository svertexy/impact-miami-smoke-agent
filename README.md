# Impact Miami Smoke-Test Agent\n\nA small, judge-friendly agent demo for Impact Miami. It reads a project dataset, summarizes delivery status, flags at-risk work, and cites the source records used for each conclusion.\n\n## What the agent does\n\n1. Loads the synthetic records in [sample-projects.json](sample-projects.json).\n2. Groups projects by status (on track, at risk, and blocked).\n3. Calculates a simple risk view from status, owner, and next action.\n4. Returns a concise project summary with source record names so a reviewer can verify each result.\n5. Keeps secrets out of the repository; runtime credentials belong in Vercel Environment Variables.\n\nThis is intentionally a smoke test: the goal is to prove the Verso/Vercel agent loop works end to end before adding a larger hackathon data source or voice layer.\n\n## Repository map\n\n- [agent-instructions.md](agent-instructions.md): the agent contract, input shape, output format, and responsible-AI constraints.\n- [sample-projects.json](sample-projects.json): synthetic records used for the demo; no private data.\n- [CLAUDE.md](CLAUDE.md): context for Claude Code and future implementation work.\n\n## Deployment\n\n- GitHub: https://github.com/svertexy/impact-miami-smoke-agent\n- Vercel project: impact-miami-smoke-agent in the Six Star Vision team.\n- Configure runtime secrets only in Vercel Project Settings → Environment Variables. Never commit API keys or paste them into documentation.\n- For OpenRouter, add OPENROUTER_API_KEY directly in Vercel’s secure Environment Variables UI, select the environments needed, and redeploy.\n\n## Demo checklist\n\n- Use a small, known dataset first.\n- Show the status summary, one at-risk item, and the cited source record.\n- Explain that the records are synthetic and that production data would be connected through a secure backend.\n- Add ElevenLabs only after the text workflow is stable; voice is an optional presentation layer, not required for the core agent.\n
